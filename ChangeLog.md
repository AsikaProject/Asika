# ChangeLog for Asika

## v20260622DEV

- **Feature**: Add workflow mode for CI/CD integration. Run `asikad --workflow` in CI pipelines to automate PR operations (labeling, merging, closing) based on repository-specific `asika_workflow_config.toml` rules. Supports GitHub Actions, GitLab CI, Gitea Actions, Forgejo Actions, Bitbucket Pipelines, and Gerrit CI. Platform detection reads environment variables to identify the platform, PR number, repository, and token. Condition evaluator supports `ci_passed`, `ci_failed`, `approved`, `has_conflicts`, `draft`, `has_label("name")` with `&&`, `||`, `!` operators. Operations execute via existing platform clients with no daemon or webhook setup required.

## v20260617DEV

- **Fix**: Resolve self-update asset lookup failure that made every `asika self-update` exit with "no binary asset found". Release tarballs are now correctly resolved by their actual `asika-<os>-<arch>.tar.gz` name and the target binary is extracted via the new `common/archive` package (streaming tar+gzip with size cap and path-traversal protection). The extracted binary is verified against `<binaryName>-<os>-<arch>.sha256sum`, which the release workflow computes over the bare binary rather than the tarball.
- **Security**: Introduce `version.Channel` ldflags injection (`release` | `package` | `manual`). Self-update is now blocked for deb/pkg/Inno/Docker installs (`package` channel) and for plain `go build` outputs (`manual` channel); users are guided toward `apt`, `brew`, `choco`, or `docker pull` instead. Release tarball builds retain the `release` channel and continue to self-update. The web `/api/v1/update/check` endpoint reports the channel and a human-readable reason.
- **Fix**: CLI self-update now installs atomically via a sibling `.new` file with `fsync` before rename, mirroring the daemon-side installer. Restore-from-backup failures surface as `CRITICAL` with exit code 2 and explicit manual-recovery instructions instead of being silently swallowed.
- **Fix**: Web-triggered self-update now refuses concurrent runs with HTTP 409 and removes the dead `updateProgressMap`/`UpdateProgress` scaffolding.
- **Fix**: Release workflow now also publishes `asika-<os>-<arch>.sha256sum` so CLI upgrades can verify the `asika` binary (previously only `asikad-*` checksums were generated).
- **Fix**: Rewrite `package-deb`/`package-pkg`/`package-inno`/`package-docker` jobs to build their own `Channel=package` binaries instead of reusing the release-tarball artifacts. This stops package-managed installs from inheriting the self-update capability.
- **Fix**: Harden the release job against silent asset loss. `cp ... 2>/dev/null || true` is removed, every package job ends with a `Verify package output` step, and the release job refuses to publish when any expected tarball, checksum, deb, pkg, or setup.exe is missing. Build/package matrices now use `fail-fast: false` so a single failing platform no longer cancels siblings.
- **Build**: `build.sh` gains a `build-package` subcommand that emits `Channel=package, Enabled=false` binaries for local packaging tests.
- **Fix**: Replace the stub `isNewer` (which only compared for string inequality) with a real date-aware version comparison under `common/version`. `Compare` parses the `YYYYMMDD[SUFFIX]` grammar and orders same-day releases by suffix priority (HF > CVE > plain > DEP > DEV); malformed input falls back to lexical ordering so the function never panics. `IsUpgradeable` enforces downgrade protection and the project dev-policy rules: dev builds are always upgradeable to a release, but a release is never upgradeable to a dev build.
- **Refactor**: Unify the "should we offer an upgrade?" decision across all three entry points. CLI `self-update`, Web `CheckForUpdate`, and the background `checkAndNotify` now all call `version.IsUpgradeable`/`IsDevBuild`. The Web endpoint's local `isDevVersion` copy is removed.
- **Fix**: Background `checkAndNotify` previously spammed "new version available" notifications for dev builds because it had no dev-skip check. It now exits early when `version.IsDevBuild` is true, matching the Web UI behaviour. It also authenticates against the GitHub API with `cfg.Tokens.GitHub` when configured, replacing the anonymous call that regularly hit 403/429 rate limits, and treats non-200 responses as a clean skip instead of trying to decode an error body.

## v20260615DEV

- **Fix**: Block draft PRs from being merged by the queue. `MarkDraft` now removes the PR from the merge queue, and `ShouldMerge` short-circuits on `IsDraft` as a defensive gate. Previously, marking an already-queued PR as draft still let the queue merge it once approvals/CI passed — violating the draft PR contract.
- **Fix**: Stabilise queue out-order. `CheckQueue` now sorts same-priority items by `AddedAt` (FIFO), matching the order exposed by `GetQueueItems` to the UI. Previously the actual merge order did not match what users saw.
- **Fix**: Batch merge now honours configured merge strategy. `batch_merge` validates the `method` argument against `{merge,squash,rebase}` and falls back to `queue.SelectMergeMethod` (rules → default → platform default) when `method` is empty. Also skips draft PRs. Previously batch merge hardcoded `"merge"`, bypassing `MergeStrategyRules`/`DefaultMergeMethod`/`FastForwardOnly` rebase.
- **Security**: Move `trigger-ci` endpoint from `prsExtra` (viewer-writable) to `prsMerge` group (`RequirePermission("merge")`). Only operator/admin can trigger CI now; viewers could previously call the endpoint.
- **Security**: Scope Gerrit Change-ID lookup to the caller's repo group. Endpoint moved from `protected.GET /gerrit/change/:change_id` (auth-only, full-table scan) to `protected.GET /repos/:repo_group/gerrit/change/:change_id` (with `RequireRepoGroupAccess`/`RequireRepoAccess`/`RequireSpaceAccess`), and the handler now uses `BucketForEachPrefix` so PRs in other tenant groups are never inspected or returned.
- **Fix**: Escape Mermaid node labels in the dependency-graph endpoint. PR titles and PR IDs are now sanitised (quotes/backslash/newline escaped, ID character set restricted) to prevent Mermaid source injection from external PR data.
- **Fix**: `asika queue priority` CLI now parses the priority argument with `strconv.Atoi` and validates the 0–100 range before encoding the body with `json.Marshal`. Previously the raw CLI argument was string-substituted into a JSON template.
- **Fix**: `auto-label` returns HTTP 500 when the platform client is nil instead of falsely reporting `"labels applied"`. Response now includes `applied` and `failed` counts.
- **Fix**: Tighten `webhook.filter.matchBranchPattern` to escape regex metacharacters before substituting `*` → `.*`. Patterns containing `(`, `)`, `+`, `?`, `[`, etc. now match their literal form instead of silently failing to compile.
